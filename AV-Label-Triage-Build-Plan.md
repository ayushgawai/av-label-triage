# AV Label Triage — build specification and agent handoff

**Release objective.** A perception data manager opens one confirmed missed pedestrian, mines a queue worth reviewing, and commissions an independent audit of a frozen batch. Each conclusion links back to frames, reviewer decisions, a label policy, and a reproducible run. A team can run this on its own images and COCO boxes locally. A public visitor can explore a completed investigation in their browser.

**First user.** A QA lead in Perception ML Operations must decide whether to reopen part of a labeling delivery. Nuro publicly assigns this team responsibility for distinguishing isolated label errors from systemic process problems. The tool provides evidence about scope. A process-cause claim also needs provenance and investigation. [Nuro team description](https://www.linkedin.com/jobs/view/senior-program-manager-perception-data-operations-at-nuro-4462338800), [Carl Betzler’s post](https://www.linkedin.com/posts/carlbetzler_hiring-activity-7427435165469122561-syz_)

**First release boundary.** One incident type, missing pedestrian boxes in 2D driving images. The product accepts image batches and sequence metadata when available. Use images as the audit unit for v1. A clip-level product would need a new clip sampling frame and complete inspection of the selected clips. Support additional classes through explicit class-policy adapters after v1 works.

## 1. Prior art and the contribution to demonstrate

| Project | Capability to build on | Engineering decision |
|---|---|---|
| ReChecked | Validated pedestrian annotations for a KITTI subset, soft reviewer probabilities, comparison scripts and evaluation of error-detection methods. | Primary external benchmark. Match its published evaluation settings and show results alongside its approach wherever the evidence units align. [Repository](https://github.com/JonathanKlees/rechecked), [paper and examples](https://osvia.org/ReChecked/) |
| FiftyOne | Its detection workflow flags plausible missing ground-truth boxes from unmatched predictions and supports visual inspection. | Offer COCO/JSONL exports for existing tools. Use detector disagreement as a serious baseline. Label a comparison as FiftyOne only if its actual implementation ran. [FiftyOne tutorial](https://docs.voxel51.com/getting_started/object_detection/03_finding_mistakes.html) |
| Cleanlab ObjectLab | Scores object-detection annotation quality using predictions and existing labels. | Optional isolated benchmark environment. Follow the package’s expected prediction format and out-of-sample guidance. Record the version, compute budget and eligible population. [Cleanlab tutorial](https://docs.cleanlab.ai/stable/tutorials/object_detection.html) |
| CVAT | Annotation, review and quality comparisons against selected ground-truth frames. | Export selected images, stable IDs and proposed boxes for a correction job. Test reimport of decisions separately from publication of revised labels. [CVAT quality control](https://docs.cvat.ai/docs/qa-analytics/auto-qa/) |
| Active testing research | Selection probabilities matter when inferring population quantities from selectively reviewed examples. | Start with a fixed probability audit, which can be tested exactly on a finite population. [Kossen et al.](https://proceedings.mlr.press/v139/kossen21a/kossen21a.pdf) |

The contribution to test is **incident-conditioned repair retrieval plus an independently verifiable estimate of the affected share**, with both tied to the same release and label policy. Open-source users already have detectors, similarity search, and annotation editors. Winning on a comparison requires showing additional confirmed errors per reviewer budget or a better operational decision.

## 2. Data and licensing

**Primary proof — KITTI + ReChecked.** Inspection of the authors’ repository at commit `1321946698296416d0495999d000dec2deea5e4d` found 3,078 rows in validated_gt.csv across 761 distinct image filenames. The authors’ split JSON lists 1,497 validation image IDs. The CSV includes soft probability, pixel height and box coordinates. These are inventory counts. A missing row for an image does not establish that experts exhaustively reviewed it and found no omission. Generate original boxes and ignore regions from the local KITTI labels using the upstream procedure. Select and document the eligible population independently of the presence of validated boxes. [Validated file](https://github.com/JonathanKlees/rechecked/blob/1321946698296416d0495999d000dec2deea5e4d/data/validated_gt.csv), [split](https://github.com/JonathanKlees/rechecked/blob/1321946698296416d0495999d000dec2deea5e4d/data/train_val_split.json), [upstream comparison](https://github.com/JonathanKlees/rechecked/blob/1321946698296416d0495999d000dec2deea5e4d/compare_annotations.py)

Freeze an initial external evaluation setting: reference pedestrian probability at least 0.8, box height at least 40 pixels, exclude relevant DontCare overlap using the upstream intersection-over-candidate-area rule at 0.5. Record that these are benchmark settings. Reproduce the upstream missed-versus-misfitting classification and log any difference. Separate a *known reference omission*, an *unmatched candidate awaiting inspection*, and a *human-confirmed negative*. Run sensitivity checks at the authors’ alternative confidence/size settings. KITTI distributes its data under CC BY-NC-SA 3.0. Provide an adapter, pinned references and local-data instructions. Keep original data terms visible alongside the license for project code. [KITTI terms](https://www.cvlibs.net/datasets/kitti/), [ReChecked guide](https://github.com/JonathanKlees/rechecked)

**Secondary replication — Udacity + Roboflow.** Roboflow reports 15,000 images and corrections across multiple object categories. Udacity documents distinct source datasets and describes educational use. Treat this as independent replication after a data feasibility check: match original and corrected frames by decoded-pixel hash when possible, verify resized/re-encoded pairs by geometry and visual checks, map class definitions, and publish the counts of accepted, ambiguous and unmatched pairs. Manually inspect a stratified sample of changed boxes. Avoid assuming all revisions are omissions. If pairing is unreliable, publish the alignment report and retain KITTI as the external benchmark. [Udacity annotation readme](https://github.com/udacity/self-driving-car/blob/master/annotations/README.md), [Roboflow correction](https://public.roboflow.com/object-detection/self-driving-car)

**Owned fixtures and public demo.** Make a deterministic tiny scene generator with boxes, excluded zones, difficult negatives and an exact truth table. For a visually persuasive public Space, add team-owned or explicitly redistributable street imagery with a documented human box pass. Record image provenance, attribution and public-display terms per asset. If an omission is deliberately introduced into a real photograph, identify it in the UI as seeded. Package upstream research images separately for local reproduction. The synthetic set proves correctness; the real benchmark tests utility.

**Customer adapter.** Minimum input is an image directory, COCO detection annotations, a human-readable class map and a dataset revision. Optional manifest columns include drive ID, time, acquisition batch, guideline version, reviewer source and ignore regions. Keep missing fields unknown. Disable conclusions that require unavailable metadata. Show image counts on image-only data. Enable encounter counts only for verified track IDs or a separately validated grouping algorithm.

## 3. Architecture and contracts

Use a Python package with a Typer CLI and a local FastAPI service. A React/TypeScript viewer consumes a small common API that can also read a static replay bundle. Use SQLite for transactions and review history, Parquet for bulk immutable records, NumPy for exact cosine search, and local paths for media. Precompute inference in restartable jobs. Measure where an ANN index or GPU is needed before adding a service dependency.

| Module | Owns | Required contract |
|---|---|---|
| ingest and policy | COCO/KITTI adapters, media hashes, category mappings, coordinate transformations, versioned eligibility rules | Stable source image IDs, local xyxy pixel coordinates with explicit bounds, original dimensions, release hash, data-quality report |
| propose and retrieve | Detector proposals, contextual crop embeddings, seed search and rank fusion | Candidate ID, frame ID, bbox, per-signal ranks, source model and revision, policy outcome, reason codes |
| review | Incident seed, scope, review assignment, human decisions and superseding decisions | Immutable decision events. States include omission, already labeled, localization error, out of scope and unresolved. Include region and policy revision |
| audit | Frozen population, sampling strata, fixed sample, blinded decisions, estimator and interval | Every selected image, including images with zero proposals, has a known inclusion probability. Store draw seed, manifest hash and completion state |
| benchmark | Hidden references, evaluation matching, baselines, uncertainty, run manifest | Independently invocable scorer with a private input path. Only the scorer and designated adjudication workflow may see reference corrections |
| report and UI | Findings, queue, full-frame audit, run export and replay | Same evidence IDs and counts through CLI, local API and static bundle. Every public chart can open its contributing records |
| ontology adapter | Relational read views, term mappings, certified calculations and Q&A checks | Compare each supported answer with a deterministic query. Preserve the approved policy version for every result |

Core tables: releases, images, source_annotations, policies, proposals, incidents, review_events, audit_designs, audit_draws, audit_decisions and run_manifests. Composite keys include release and model/config revision. Hash inputs and write bulk output to staging before atomic promotion. Resume completed shards by fingerprint. Use transactional review writes, idempotency keys and optimistic revision checks for editing. Test an interrupted index build and simultaneous review updates.

Proposed normal entry points, exercised in CI:

~~~sh
avtriage demo
avtriage import coco --images ./images --annotations ./original.json --policy pedestrian.yml
avtriage index --release RELEASE --device cpu
avtriage serve --release RELEASE
avtriage benchmark --config recipes/kitti-rechecked.yml
avtriage audit-report --incident INCIDENT
avtriage export --incident INCIDENT --format replay
~~~

Document a second entry point that imports precomputed COCO predictions and skips detector inference. A newcomer should be able to try the fixture demo without credentials, external model calls or a GPU. Keep the reference evaluator and data download steps outside the lightweight install.

## 4. Algorithm and training

1. **Seed and eligibility.** A reviewer draws one missing box and selects the policy. Compute a crop with modest surrounding context, record the seed region, and exclude it and its known duplicate group from scored discoveries. Apply class eligibility and ignore-region rules. Route ambiguous category mappings and potential box shifts to review. A COCO “person” prediction in a cyclist annotation may be a correctly labeled road user under the target policy.
2. **Propose broadly.** Use frozen RT-DETR-R50 for person proposals. Match against existing annotations on the same frame and compatible class using deterministic one-to-one matching. Save unmatched proposals, marginal overlaps and crowded-region conflicts separately. Tune confidence, matching thresholds and proposal cap on development data. Keep low-score proposals for analysis. Measure the fraction of known omissions reachable by any candidate; this ceiling bounds the retrieval method. [RT-DETR model card, Apache-2.0](https://huggingface.co/PekingU/rtdetr_r50vd)
3. **Retrieve regions.** L2-normalize DINOv2-small CLS embeddings of proposal crops; use cosine similarity to the seed. As a detector-independent option, search a small multiscale grid of overlapping candidate crops. Evaluate its added reach and CPU cost; a retrieved tile is a search hint, so the reviewer draws the final box. Always include a full-frame view. Exact search is the reference implementation. [DINOv2-small model card, Apache-2.0](https://huggingface.co/facebook/dinov2-small)
4. **Rank and diversify.** Start with reciprocal rank fusion of detector disagreement and seed similarity, with a fixed constant, e.g. 60, and development-set weights. A missing signal contributes zero. Merge overlapping proposals within an image, preserve provenance, and initially emit one highest-ranked item per image. Cap neighboring frames when sequence metadata exists; count each reviewer action. Log each component so the interface can explain a result. Compare a later relevance-feedback variant against the frozen queue using the same number of reviewer actions.
5. **Training decision.** V1 trains no detector and needs no private data. Pin the two model commit SHAs, preprocessing, image size, package versions and device settings. If enough adjudicated development incidents exist, try a regularized logistic reranker over similarity, proposal confidence, overlap, size and contextual features, trained on incident-disjoint examples. Use grouped cross-validation and a held-out calibration split if emitting probabilities. Adopt it only with a reproducible benefit over frozen fusion. Rank scores alone have no prevalence interpretation.
6. **Inspect failures.** Save examples of tiny distant people both models missed, riders retrieved as pedestrians, crowd zones, mismatched boxes and repeated near-identical frames. Track policy rejection rates and reviewer time. A model that keeps finding the same easy pedestrian is expensive even when its top-ranked frames look convincing.

### Gemini Flash for rare visual ambiguities

Show the local repair queue immediately. When the team enables the cloud adapter for a release, consider only candidates in the active review shortlist. Escalate when a named policy distinction would change the review decision and the existing signals leave a specific, visually answerable question. A reviewer can also use “Ask Flash” on a selected case. Deduplicate by encounter when available. Low detector confidence alone is insufficient. Keep the independent audit blind to all Flash results.

Start with the person/bicycle conflict. Given a person proposal overlapping an existing cyclist box, send a context crop and a full frame with a neutral region marker. Ask whether the person is mounted, walking beside the bike, or unclear. Request one observable cue; hide source class and expected answer from the model. For an authorized sequence, include one or two nearby frames in the same request if already available. Apply the release-specific class policy in code and attach a second opinion to the review card. A human confirms any amendment. Preserve uncertain cases for review.

Proposed pilot defaults are ten distinct cases per incident and two concurrent calls. Auto and manual requests share the cap. Reserve slots transactionally; meter retry attempts separately with a bounded attempt limit, deadline and provider backoff. Prioritize interactive requests. Cache by image bytes, region, context, observation question, model version and prompt revision. Run requests asynchronously; timeouts leave a reviewable local candidate. Public replay uses recorded, identified responses and ships without a provider key.

Benchmark blinded human decisions on a frozen set of ambiguous encounters. Counterbalance assisted and unassisted reviews across reviewers. Report correct decisions per reviewer-hour, erroneous downgrades of real omissions, abstention rate, share escalated, and p95 time until the second opinion appears. Also sample a few unflagged cases offline to learn what the trigger misses. Test that an ordinary import makes zero calls, concurrent duplicate requests share work, and an interrupted provider cannot stall local review. The demo should show a genuine ambiguous case, its escalation reason, visual cue, policy consequence, and human verdict.

## 5. Design the independent audit

**Decision quantity.** For a specified frozen local release or batch, estimate the fraction of in-scope images with at least one qualifying omitted pedestrian. Define the sampling universe without consulting the detector or corrected labels. A zero-proposal image remains eligible. Whole-image inspection is essential. Record policy, strata and sample size before revealing audit decisions.

For a first implementation, partition images into a few fixed score bands that include low and zero scores. Merge small bands before sampling if the budget cannot give each one positive inclusion probability. In each stratum h of size N_h, draw n_h images uniformly without replacement. The inclusion probability is n_h/N_h. Each auditor inspects the full frame with original labels and the policy, blinded to miner rankings. Resolve disagreements by second review. If a queue item overlaps the audit, obtain a fresh blinded audit decision and count its sampling probability once.

With x_h confirmed defective images in a fully reviewed draw, estimate p = sum_h [(N_h/N) × (x_h/n_h)]. Use exact finite-population hypergeometric inversion for each stratum’s possible count of defective images. Use simultaneous Bonferroni-adjusted intervals and sum their count bounds divided by N for a conservative 95% interval. Handle censused and empty strata explicitly. With unresolved sampled items, report status and sensitivity bounds by rerunning with each unknown coded zero and one. Avoid a finished point estimate until adjudication is complete. Display the planned budget, audited count, batch size and interval width. Zero findings with a small audit still leaves a positive upper bound.

This estimates a finite collection of images with a fixed-size design, including correlated frames. Generalizing to future drives or changing the sampling unit to entire drives requires a different design. Freeze audit budgets; repeated optional peeking and stopping changes interval validity. If a manager wants a rework threshold, let them set one and show how the interval compares. For a broad interval the correct outcome can be “more audit evidence needed.”

## 6. Prove the project works

**Retrieval benchmark.** Freeze policy, model revisions, budget, seeds and splits before the final run. Group by source drive where possible, otherwise by verified duplicate clusters and document residual dependence. Select development and final groups separately. Use several predeclared seed incidents spanning size/context, report seed availability, and exclude seed images and duplicates from discovery credit. For a cold-start test, allow exactly one adjudicated positive. All methods receive the same source data, compute disclosures and review budget. Keep reference corrections inaccessible during mining; verify ranking is unchanged when the reference path is absent.

**Baselines.** Uniform random image review; unmatched detector confidence; DINO crop similarity alone; frozen fusion; fusion with optional independent tiles. Include a run of ReChecked’s reference procedure and compare method outputs only on compatible units. Add Cleanlab if it can be run faithfully. Full-frame random audits and suggested-box reviews have different costs; show image-level yield at equal image budgets and verified omissions per measured person-minute in the human pilot.

**Scoring.** Report known omissions reached before ranking, unique confirmed omissions in the first 25/50/100 reviewed images, precision at the chosen budget, review seconds and unique-drive coverage when available. One discovered reference box can earn credit once. Define matching coordinates, IoU threshold and tie rules. Distinguish “known corrected box recovered” from “new omission adjudicated.” Report both. Use paired comparison intervals across held-out drives or independent groups, list the number of groups, and show variation by seed. Avoid treating thousands of neighboring frames or overlapping seeds as independent experiments. Record cold indexing time, cache size, query p50/p95, tested hardware and memory.

**Audit benchmark.** Generate populations with known prevalence, including all-negative, concentrated defects, rare defects in the low-score band, near census, unequal stratum sizes and many duplicate-looking frames. Enumerate all draws on tiny populations to verify coverage at or above nominal. On larger fixtures repeat at least 1,000 preseeded draws, report empirical bias, median interval width and coverage with Monte Carlo uncertainty. On real data validate prevalence only against a fully adjudicated small finite cohort selected independently of the miner. The ReChecked correction file is a reference for known errors; completeness of a whole population must be established separately.

**Human pilot.** Have two reviewers independently inspect a blind subset with the same policy. Resolve disagreements with a documented adjudication. Record time and reasons; report the number of independent reviewers honestly. If only one reviewer is available, publish a single-reviewer pilot and leave agreement unmeasured. Publish unsuccessful baselines and a failure gallery. Claim a retrieval gain only if a predeclared comparison supports it; otherwise ship a functioning investigation/audit toolkit and describe where simpler mining won.

**Tests.** Unit-test box transforms, clipping, DontCare intersection-over-area, greedy/reference versus production matching, tile deduplication, ties, idempotent imports, monotone audit bounds, unresolved labels and missing metadata. Property-test inclusion probabilities, invariance under row reordering, census equality and zero-findings behavior. Integration-test import → index → seed → review → audit → export using owned fixtures. Browser-test keyboard review, undo as a superseding event, reopening the case, evidence links, empty queues and reduced motion. CI runs CPU-only with small frozen outputs; a separate opt-in model smoke test runs actual weights. Publish a command that regenerates every README result from a versioned run manifest.

## 7. NVIDIA Auto Ontology integration

Keep the image-processing engine local. Materialize vetted result tables into a documented PostgreSQL schema for the integration profile. Use upstream Auto Ontology to map terms, join paths and reviewed SQL attributes over these views. Pin a tested upstream revision and list its service/model prerequisites. Model the project’s policy, source revision and reviewer history explicitly. Persist computed audit estimates and bounds as outputs of the statistical library; point the semantic model to them.

Acceptance questions: “How many unique images were reopened under policy P?”, “What fraction of batch B had an omission in audit run R, with bounds?”, and “Which reviewed images were excluded by policy?” Return the population, unit, revision, SQL and evidence IDs appropriate to each answer. Include a negative test for “Which vendor caused this?” when provenance is missing. Test at least one live MCP query against pinned services and compare with golden SQL results. Label an offline replay of this exchange as a replay. [NVIDIA Auto Ontology](https://github.com/NVIDIA/auto-ontology), [MCP query interface](https://github.com/NVIDIA/auto-ontology/blob/main/docs/mcp.md)

## 8. The demo and Hugging Face release

**The opening shot:** a street image at full size. Existing annotations fade in. A reviewer boxes a visible pedestrian the original labels missed. The opening question is “How many more should we reopen?” The missing box is the seed, so the visitor immediately knows what the system is looking for.

| Time | Viewer action | Evidence on screen |
|---|---|---|
| 0–12 s | Toggle original and reviewed labels; select the seed. | Image ID, policy and disputed region. Show whether the case is historical or seeded. |
| 12–28 s | Run the recorded search and step through three results. | Animate crops back to their full-frame locations. Show detector/similarity ranks, one convincing hit, and one plausible false alarm. |
| 28–43 s | Accept one, reject one, inspect a duplicate. | Update the session’s review queue. Show actual reviewer decisions for recorded cases and mark visitor decisions separately. |
| 43–58 s | Open the independent audit and reveal its fixed sample. | Animate sampled image IDs into the score bands, including an image with zero proposals. Draw interval and denominator from the computed result. A queue click can never change the recorded audit estimate. |
| 58–70 s | Open the manager’s report and reproduce it. | Show reopen list, reviewed policy exceptions, audit bounds and a copyable run command. Link to the benchmark and failure cases. |

**Public distribution.** Ship the viewer as a Static Hugging Face Space backed by a versioned replay bundle. Let visitors change seeds among precomputed cases, inspect ranked records, and reset their own browser session. Make “recorded inference” visible. Provide keyboard controls, reduced-motion support, static poster frames and accessible text equivalents for overlays. Create a dataset card for the shareable fixture/replay artifact with its generation method, provenance, license, intended use and known gaps. Link to the original model cards; publish a new model card only if a trained reranker is actually released. Use clear licenses per component: proposed Apache-2.0 for original code, separate terms for fixtures, source datasets and weights. Prepare a Python wheel, a reproducible container, CONTRIBUTING, CITATION.cff and a short walkthrough. [Spaces](https://huggingface.co/docs/hub/spaces-overview), [dataset cards](https://huggingface.co/docs/hub/datasets-cards)

## 9. Build order and release gates

| Milestone | Deliverable | Exit test |
|---|---|---|
| M0 · Data feasibility | Pinned manifests, alignment and licensing notes, benchmark protocol | Load matching original KITTI labels and ReChecked reference; reproduce one upstream configuration. Report unavailable source artifacts explicitly. |
| M1 · Vertical slice | Local CLI, schema, review UI, owned fixture, static export | A fresh install opens a seeded case offline, records a decision, restarts, and exports the same evidence IDs. |
| M2 · Real retrieval | Frozen inference, region search, baselines, deterministic queue and bounded Flash second opinions | A real run returns traceable full-frame candidates; report ceiling and baseline yields with matched budgets. |
| M3 · Audit and evaluation | Probability draws, blinded full-frame review, estimator, held-out runner | Exact small-population tests pass; zero-proposal images can be drawn; a hidden-truth evaluator reproduces the scorecard. |
| M4 · Enterprise Q&A | PostgreSQL views, NVIDIA definitions, tested MCP adapter | Three supported questions agree with golden queries; unsupported causal attribution is identified. |
| M5 · Open-source release candidate | Static Space bundle, dataset card, wheel, Docker build, motion walkthrough | Clean install and browser smoke test pass; every number on screen resolves to a run artifact; license inventory complete. |

Prioritize M0, then the smallest end-to-end case. Parallelizable work after the schemas stabilize includes the audit estimator and viewer. A release with honest uncertainty and modest retrieval gains is more valuable than a polished video built on fabricated numbers.
