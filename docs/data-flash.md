# Optional Flash second opinion

By default there is no provider call. A local operator may explicitly create `WORKSPACE/flash-opt-in.json` with `{"enabled_releases":["RELEASE_ID"],"model":"gemini-2.5-flash","policies":{"RELEASE_ID":{"mounted":"out_of_scope","walking_beside":"pedestrian","unclear":"unresolved"}}}` and set `GEMINI_API_KEY` in the server environment. Do not commit the key. The local API checks that the proposed candidate is among the top ten active incident queue items and is a person/cyclist conflict; it constructs the context crop and neutral marked frame from hash-checked local media. `POST /api/incidents/{incident_id}/flash` with `{"proposal_id":"...","manual":true}` queues a second opinion; `GET /api/incidents/{incident_id}/flash/{proposal_id}` polls its status. Review remains usable while a call is pending. Results are separate from audit endpoints and do not become reviewer decisions. A human must confirm amendments.

The explicit policy mapping shown is an example; configure it to the release policy. The provider must return a valid mounted/walking_beside/unclear observation and a nonempty visible cue, and code attaches the configured policy outcome. This result is still only a second opinion.

The SQLite store reserves at most ten distinct case IDs per incident/release; two worker threads per process run requests, manual queued requests precede automatic queued requests, and duplicate requests within the process share the same future. Cache identity includes model, prompt revision/question, image content and region crop. Attempts and failures are persisted; each call has an HTTP timeout, a bounded retry count and short backoff. No live provider calls or human pilot have been run here. An exclusive operating-system lock prevents simultaneous Flash servers on the same workspace. Hard interruption of a misbehaving custom transport, provider-specific error handling, and a separate transactional global rate limiter remain unverified. Use mock transport only until those limits are addressed. An enabled release sends actual user imagery to the provider; opt in only where sharing is authorized.

The OS workspace lock currently requires Unix; importing and using the rest of the package remains supported without Flash on platforms without `fcntl`. The adapter has no live-provider validation or human pilot, so its provider response and timing behavior remain unverified. No real assets were sent during local tests.
